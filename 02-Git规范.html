02 · Git 工作流 & 里程碑管理

一、Git 工作流规范

1. 分支管理规范

分支用途与规则
master 仅保存挂网内容。
每次版本挂网时,需将经过软测实测的 dev 分支合并到 master。
dev 日常开发集成分支;必须通过软测实测后才允许合并至 master。
⛔ 禁止:将未经软测实测的内容直接合入 master。

2. 提交(Commit)规范

  • 聚焦单一变更目标:每次提交仅围绕一个变更目的,便于精确回滚。
    ⛔ 禁止:在一个提交中塞入大量修改。
  • 提交信息清晰简要,必须包含:
    • 目的 — 这次提交要做什么
    • 原因 — 为什么要做(背景 / 触发条件)
    • 修改范围(可选)— 影响的模块 / 文件 / 接口

3. 提交信息示例

fix(uds): 修复安全访问 0x27 服务超时退避未生效

目的:让 0x27 服务在服务端延迟时按指数退避重试
原因:实测中部分 ECU 在加密阶段响应慢,导致诊断仪直接报失败
修改范围:uds/security_access.c、uds retry 配置表
