# 汽车诊断软件开发团队 · 部门规范知识库

本仓库是 HD 部门日常开发规范的**共建源**。给诊断软件开发同事阅读、修订、继续往下补。

仓库地址：https://github.com/cnCloven/xtool-hd-standards

> 内部资料，请勿外传到仓库以外的公开渠道。

**增补或修改规范，请用仓库内的 Claude Code skill `hd-spec-docs`，不要手改 HTML 结构、不要手写 PDF 合并。**

---

## 1. 背景

部门日常工作分散在编码、Git、华为云 Bug、版本挂网、车系跟进表等环节。过去约定多靠口头和零散 Wiki，新人上手慢，脚本也读不了各品牌各写各的跟进表。

这套知识库把约定收成**可点击跳转的 HTML 章节**，再打包成**一份带目录链接和内嵌截图的 PDF** 对外分发（邮件、OA、新人资料包）。

- **HTML 是唯一源文件。** 不要打开 PDF 改字，也不要改 `build/bundle.html`。
- 跟进表的表名 / 列名固定，后续可用通用脚本读取所有品牌。
- 每次改完打出带时间戳的新 PDF，旧版进入 `backup/`。

用浏览器打开 [规范总览.html](规范总览.html) 即可在章节间跳转，不需要起服务器。

## 3. 维护方式：用 skill `hd-spec-docs`

仓库已内置 Claude Code 项目技能 **[hd-spec-docs](.claude/skills/hd-spec-docs/SKILL.md)**（路径 `.claude/skills/hd-spec-docs/`）。它负责：

- 按现有皮肤和骨架**新增 / 修改** HTML 章节
- 把截图以相对路径插入正文（打包时再编码进 PDF）
- 更新该章「变更记录」和总览索引
- 调用 `tools/build_pdf.py` 打出带跳转链接、内嵌图片、时间戳文件名的 PDF，并把往期 PDF 归档到 `backup/`

HTML 约定、章节模板也在该 skill 目录里，由 skill 自己读取，不必在 README 里再抄一遍操作步骤。

### 怎么用

1. 克隆本仓库，用 **Claude Code** 打开仓库根目录（不要只打开某个 HTML）。
2. 第一次打包 PDF 前，本机装好 Python 3，并执行：

   ```bash
   python -m pip install playwright pypdf
   python -m playwright install chromium
   ```

3. 用自然语言说明意图即可，例如：

   | 你想做的事 | 直接这样说 |
   |---|---|
   | 改已有章节 | 「在 05 团队协作里给项目计划加一列 xx」 |
   | 新开一章 | 「新增一章 07-xx 规范，内容是……」 |
   | 插入截图 | 「把 `images/` 里这张图嵌到 04 版本发布的 OA 标题那一节」 |
   | 只重新出 PDF | 「把规范打成 PDF」 |

4. 看一眼生成的 `柴油日常开发规范_时间戳.pdf`：封面卡片能跳、截图还在。
5. 提交并提 PR 到 `main`（尽量一章一次，避免和别人改同一个 HTML）。

不要手改章节编号规则、不要把 base64 大图贴进源 HTML、不要用 Word / Markdown 当源文件。这些 skill 都会处理。

```
01-编码规范.html … 07-*.html  各章源文件

images/                       截图原图（HTML 用相对路径引用）

backup/                       往期 PDF
.claude/skills/hd-spec-docs/  维护 skill（优先走这里）

```

`.gitignore` 已排除本机权限文件、`build/` 中间产物和 `__pycache__/`。
