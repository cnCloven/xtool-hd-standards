07 · 离职交接规范

1. 适用范围

  • 员工离职、调岗、长期借调，导致其负责的诊断软件 / 车系 / 工具链需要移交给他人。
  • 一个交接人、多个项目时：每个项目单独复制一份模板填写，不要把多个项目挤在同一份文档里。
✓ 交接完成的标准：接收人能独立推进后续工作，且本章第 4 节验收项全部勾选。

2. 必须使用项目交接模板

空白件位置： templates/项目交接模板.html （用浏览器打开即可填写）。
  • 交接人从仓库复制该文件到自己的工作目录（或另存），不要改仓库里的空白件。
  • 在浏览器中填写；右上角「保存到文件」后，把下载下来的 HTML 发给接收人 / 主管（也可「打印 / 导出 PDF」）。
  • 模板内填写内容默认只存在本机浏览器，未保存到文件前不要关机或清缓存。
⛔ 禁止：用口头交接、聊天记录或自制表格替代本模板。

3. 模板必须覆盖的章节

模板已按下列结构排好，交接人按提示填全；空项须写明「无」或「不适用」，不得留白蒙混。

章节要求
封面 部门、编写人、编写日期、审核人（主管）；修改记录从 V1.0 起。
一、交接基础信息 交接人、接收人、主管负责人、涉及项目、启动日期、计划完成日期。
二、项目全貌 业务背景、目标与交付物、范围与约束、干系人及诉求、关键里程碑与决策。
三、项目进度 当前阶段、已完成与已验收、未完成任务（含计划时间 / 依赖）、后续排期、待决策卡点、纪要存放路径。
四、项目资源 文档路径与版本、系统账号与权限移交方式、物料（原型 / 配置 / 脚本）、合同与外部联系人。
五、问题与风险 现存问题（原因 / 已处理 / 状态 / 建议）、潜在风险（等级 / 影响 / 预案）、历史踩坑。
六、交接验收核对 三方（交接人、接收人、主管）逐项勾选，全部达成视为合格。

4. 流程与验收

  1. 主管指定接收人，约定计划完成日期。
  2. 交接人复制模板，按第 3 节填完，保存 HTML（或导出 PDF）。
  3. 与接收人对照文档走查：账号能登、路径能开、待办能接。
  4. 主管审核封面「审核人」并确认第 6 节勾选齐全。
  5. 交接文档随项目资料一并归档（跟进表、代码仓库说明见 05 团队协作与文档、 02 Git 工作流）。
⚠ 账号与权限：模板里的账号信息按公司保密要求填写（可写「已当面移交，不落文档」），禁止把密码明文发到公共群。
