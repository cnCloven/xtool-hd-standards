2. C++ 代码规范(C++14, No Exceptions)

2.1 异常禁令

  • 由于 ndk 暂不支持,禁止使用 try / catch / throw。
  • 建议使用 Result<T> 或 ErrorCode 模式传递错误。
  • 调用返回 Result<T> / ErrorCode 的函数后必须立即检查,禁止忽略返回值。

2.2 资源管理

  • 禁止裸 new / delete。
  • 使用 RAII 管理资源,优先 std::unique_ptr / std::make_unique。
// ✅ DO
std::unique_ptr<Session> session = std::make_unique<Session>();

// ❌ DON'T
Session* session = new Session();
delete session; // 容易遗漏

2.3 头文件与命名空间

  • 头文件必须包含 #pragma once。

2.4 外部数据与健壮性

  • 对外部数据(文件、协议响应)必须做边界检查。
  • 必须考虑中断、超时和重试策略。

3. 注释规范

3.1 通用原则

  • 注释解释"为什么",而不是"做什么"(代码自解释即可)。
  • 提交前必查:注释是否解释了"为什么"而非"做什么"?

3.2 公开 API 注释要求(Doxygen 风格)

每个对外公开的类 / 函数 MUST:
  • 说明用途(What & Why);
  • 说明参数、返回值、错误码;
  • 标记线程安全与使用约束。

3.3 公开 API 注释样例

/**
 * @brief 发起 UDS 安全访问请求(0x27 服务)。
 *
 * 在加密传输阶段向 ECU 请求安全访问;失败时按指数退避重试。
 *
 * @param ecuId      目标 ECU 标识。
 * @param subFunc    安全访问子功能(如 0x01 请求种子)。
 * @param timeoutMs  超时时间(毫秒),必须 > 0。
 *
 * @return Result<SecurityAccessResp>
 *         成功返回响应对象;失败返回错误码:
 *         - ErrorCode::Timeout       超时
 *         - ErrorCode::NegativeResp  ECU 返回否定响应(NRC)
 *         - ErrorCode::InvalidParam  参数非法
 *
 * @note 线程安全:可并发调用,内部无共享可变状态。
 * @par 使用约束
 *       调用前必须已建立诊断会话,否则返回 ErrorCode::InvalidState。
 */
Result<SecurityAccessResp> RequestSecurityAccess(uint16_t ecuId,
                                                 uint8_t  subFunc,
                                                 uint32_t timeoutMs);
⚠ 上述样例覆盖了 3.2 的全部要求:用途(brief)、参数(param)、 返回值与错误码(return)、线程安全(note)、使用约束(par)。
